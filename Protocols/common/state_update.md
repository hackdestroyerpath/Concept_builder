# Протокол обновления состояния

[Назад к README](../../README.md)

## Назначение

Основной протокол сохранения нужного `state`, то есть файла состояния, перед ответом. Состояние нужно для восстановления нового чата; текстовое обещание без записи не считается сохранением.

## Когда обновлять state

State обновляется до ответа, если изменились фокус, registry, статус issue/concept, требования, план, решение, договор, отчёт, export, активные протоколы, правила контекста или следующий ожидаемый шаг.

## Порядок сохранения

1. Определить нужный state-файл.
2. Обновить фазу, фокус, идентификатор сущности, ожидаемое действие, следующий шаг и статус.
3. Синхронизировать `source_files` и `output_files`.
4. Увеличить `state_revision`.
5. Обновить `last_persisted_at` перед записью.
6. Пересчитать `state_hash` по [State schema](../../State/state_schema.md).
7. Записать файл через GitHub Connector.
8. Проверить commit SHA или перечитать файл.
9. Писать `persisted=yes` только после успешной записи.

## Поведение при ошибке

Если запись не выполнена, ответ должен содержать: `Persistence не выполнен: state не сохранён.` После этого issue, export и финальная проверка не закрываются как успешные.

## Покрытие hash

Hash покрывает весь JSON состояния кроме поля `state_hash`. Значение `pending`, пустая строка и `null` недопустимы для активного состояния.
